A task file is a Markdown document containing the objective, constraints, available resources, and expected deliverables. `--task` submits its contents as the initial conversation input.

## Use the SGLang example

The <a href={taskFile} download="sglang-throughput.md">SGLang throughput task</a> targets Qwen3.5-35B-A3B in BF16 on MetaX C500 GPUs. It compares request concurrency 1 and 16 within a 24-hour budget, with separate limits for each service candidate and all concurrent experiments.

General tasks use `default`. For this example, choose `inference` and name the session. Run from the ForeRSI repository root:

```bash
fore-rsi --workflow inference \
  --name "SGLang throughput" \
  --task tasks/inference-optimization/sglang-throughput.md
```

File paths are relative to the directory where you run the command. Use an absolute path when the task file is stored elsewhere, and quote paths containing spaces.

## Write your own requirements

Describe the result you want before listing implementation preferences. A useful task includes:

- The objective and how the result will be evaluated.
- Conditions that must remain unchanged, such as answer quality or latency requirements.
- The environment, resources, and time available for the work.
- The outputs you need, such as code, a configuration, measurements, or a report.

For inference optimization, identify the service, model, representative workload, and measurement command. Separate requirements from ideas to investigate so an untested suggestion is not treated as a fixed constraint.

## Add context

Continue the conversation after startup to clarify requirements or share results. Type `@` in the editor to find and reference files from the project.

Task files describe the work. [Session names](../sessions/) help you find the conversation that received them.
