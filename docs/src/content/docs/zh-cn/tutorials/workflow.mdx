在 ForeRSI 仓库中安装依赖：

```bash
npm install
```

## 定义模块

工作流模块默认导出一个 `ForeRsiWorkflow`。`taskSchema` 在共用任务字段上增加具体要求；`build()` 提供原生入口任务，以及注册这些任务的扩展。

原生任务与 `ForeRsiWorkflow` 使用相同的检查点和结果类型，示例中分别是 `Checkpoint` 和 `string`。

实际执行的工作写在任务的阶段函数中。`build()` 准备任务定义，也可以通过传入的 `WorkflowContext` 获取任务名称和产物目录。

## 加载与装配

在仓库根目录执行：

```bash
node --input-type=module <<'JS'
import { loadWorkflow, assembleWorkflow } from 'fore-rsi/workflows';

const loaded = await loadWorkflow(
  new URL('./examples/workflows/task-brief.ts', import.meta.url),
);
const prepared = await assembleWorkflow(loaded.definition, {
  taskName: 'brief-example',
  taskDirectory: new URL('./output/brief-example/', import.meta.url),
});

console.log(prepared.entry.definition.name);
JS
```

命令输出 `task-brief.compose`，表示模块已加载、任务字段已编译成校验规则，入口任务也已注册。

`loadWorkflow()` 从模块所属的 `package.json` 读取版本。`assembleWorkflow()` 返回入口任务、Durable 注册表和任务数据校验器。任务宿主利用这些结果校验要求，并创建或重新打开持久化执行。

## 扩展工作流

在 `taskSchema` 中加入领域特有要求，通过返回的扩展注册更多原生任务和工具，同时确保入口任务也已注册。

工作跨越多个阶段时，将下一阶段需要的数据保存到任务检查点。Pi Durable 提供阶段、等待和持久化机制，工作流负责定义具体动作及其恢复行为。

继续阅读[任务数据](../../reference/task-data/)和 [API 参考](../../../api/)。底层执行接口见 Pi Durable 的[任务与扩展指南](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)。
