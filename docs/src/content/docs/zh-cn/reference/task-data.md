工作流代码接收结构化任务数据。用户可以通过 [Markdown 任务文件](../../guides/tasks/)表达要求，再由应用将整理后的数据交给工作流。

## 任务要求与运行记录

`TaskRevision` 包含目标、约束、团队配置、环境设置和修订号。工作流通过 `taskSchema` 补充领域特有字段。

`Task` 进一步记录稳定的任务名称、工作流名称与版本、执行状态、首次启动时间和成员信息。`workflowTaskId` 将任务关联到 Pi Durable 中的入口任务。

`assembleWorkflow()` 组合共用任务要求与工作流字段，返回校验器。宿主在创建原生入口任务前，使用它检查任务数据。

## 团队配置

`AgentTeamSpec.roles` 将角色名称映射到执行配置。每项配置指定 Agent 后端、模型、推理强度和活跃槽位数，角色名称由工作流定义。

`AgentTeam` 还包含成员记录。每个 `AgentInstance` 都有稳定名称，并记录所关联的会话、工作流任务、已应用的任务修订和生命周期状态。槽位数限制同时活跃的工作，不限制可以保留多少历史会话。

## 资源与时间限制

资源约束区分三个范围：

- `machineConstraints`：每台机器的并发使用上限。
- `perExecutionConstraints`：一次完整工作负载的上限，包括与之相关的作业和服务。
- `totalExecutionConstraints`：所有受管理工作负载的并发总量上限。

在一个范围内，`null` 表示不增加超出外层约束的限制。允许使用的机器或 GPU 选择条件集合为空时，表示没有可匹配的资源。

`maxHostMemory` 使用数值时单位为 GB，也可以用带单位的字符串。`minLinkSpeedGbps` 表示协商链路速率，不是预留带宽。

`timeBudgetSeconds` 从首次执行开始计算实际经过的时间，包含暂停时间；恢复时保留原始开始时间。值为 `null` 时没有时间上限。

完整的导出类型、字段说明和状态取值见 [API 参考](../../../api/)。
