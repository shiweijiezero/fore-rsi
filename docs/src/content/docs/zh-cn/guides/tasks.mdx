任务文件是描述目标、约束、可用资源与预期交付物的 Markdown 文档。`--task` 会将文件内容作为对话的初始输入提交。

## 使用 SGLang 示例

仓库提供了 <a href={taskFile} download="sglang-throughput.md">SGLang 吞吐优化任务</a>，包含两小时预算、质量与延迟要求，以及四个 Explorer、四个 Worker 和两个 Verifier 的团队配置。

通用任务默认使用 `default`。这个示例选择 `inference`，并为会话命名；在 ForeRSI 仓库根目录执行：

```bash
fore-rsi --workflow inference \
  --name "SGLang 吞吐优化" \
  --task tasks/inference-optimization/sglang-throughput.md
```

相对路径以执行命令的目录为基准。文件放在其他位置时，可以使用绝对路径；路径中有空格时，用引号包起来。

## 编写自己的要求

先写希望得到的结果，再补充实现偏好。通常需要说明：

- 目标，以及如何判断结果是否达到要求。
- 必须保持的条件，例如回答质量和延迟要求。
- 可使用的环境、资源与时间预算。
- 需要交付的代码、配置、测量结果或报告。

推理优化任务应写清服务、模型、代表性工作负载和测量命令。将必须满足的要求与待尝试的想法分开，便于比较方案，而不把未经验证的建议当成固定约束。

## 补充材料

启动后可以继续通过对话澄清要求或分享结果。在输入框中键入 `@`，查找并引用项目文件。

任务文件描述要做的工作，[会话名称](../sessions/)则帮助你找回接收这些要求的对话。
